# 前端关键路径深度代码审计与测试规范

对前端核心业务路径进行静态类型校验、状态三态检查、竞态防范、内存泄漏与错误处理深度审计。

---

## 🧭 执行流程

```text
Phase 1: 路径与环境确认 ➔ Phase 2: 凭据与配置 ➔ Phase 3: 深度代码审计 ➔ Phase 4: 输出标准测试报告
```

### Phase 1：关键路径与环境确认

1. **扫描核心流**：检索路由与 `pages/`，列出关键路径（如：登录鉴权、检索筛选、CRUD 操作、表单提交流程）；
2. **确认环境**：本地开发 (dev) / 预发布 (staging) / 生产 (prod)。

### Phase 2：鉴权与环境变量注入

| 认证方案 | 注入与模拟方式 |
|---|---|
| **Bearer Token** | `localStorage.setItem('token', TOKEN)` 或请求拦截器注入 |
| **Cookie Session** | 配置 `withCredentials: true` |
| **API Key / Header** | 环境变量 `VITE_API_KEY` 或自定义 Header |

### Phase 3：深度代码分析重点

| 检查维度 | 审计重点与缺陷特征 |
|---|---|
| **数据加载与竞态** | `useEffect` / `watch` 依赖完备性；连续快速请求是否有 AbortController 或过期丢弃机制 |
| **CRUD 联动刷新** | 创建/更新/删除操作后列表是否正确重新请求，避免因缓存未刷新 |
| **错误吞没与兜底** | 严禁 `.catch(() => {})` 静默吞错导致白屏；必须提供可见的错误提示 |
| **状态三态完备性** | Loading（骨架屏）、Error（重试按钮）、Empty（空状态提示）完整覆盖 |
| **内存与事件泄漏** | 组件卸载时定时器、原生事件监听、未完成 Promise/订阅是否完全清理 |
| **API 契约一致性** | 路径参数、业务错误码（HTTP 200 下 `code !== 0`）拦截与类型对齐 |
| **敏感信息安全** | 严禁在客户端代码中硬编码私有 Secret 或 Token |
