# 关键路径深度代码调试与测试

---

## Phase 1：确认关键路径与测试环境

1. **识别关键路径**：
   - 扫描 `src/pages/`、路由配置与核心组件，列出核心业务流（如：登录授权、数据检索、CRUD 操作、表单提交等）。
   - 向用户展示推断出的关键路径列表，确认测试范围。

2. **确认测试环境**：
   - 本地开发环境（localhost / dev）
   - 预发布环境（staging / pre）
   - 生产环境（production）

3. **明确测试目标**：
   - 确立每条路径的预期结果与边界条件，声明关键路径必须全部通过。

---

## Phase 2：鉴权与环境变量准备

根据项目实际使用的认证机制配置测试凭证（若无需登录则跳过）：

| 认证方案 | 注入与模拟方式 |
|---|---|
| JWT / Bearer Token | `localStorage.setItem('token', TOKEN)` 或请求头注入 |
| Cookie Session | 注入 `document.cookie` 或在 API 客户端配置 withCredentials |
| URL Access Token | 在测试 URL 添加 `?access_token=TOKEN` |
| 自定义 Header / API Key | 配置环境变量 `VITE_API_KEY` 或注入请求拦截器 |

---

## Phase 3：深度代码分析

对每条关键路径涉及的**所有相关文件**逐一深入分析，记录**文件名 + 行号**。

### 3.1 静态与类型检查
运行 `npx tsc --noEmit` 或项目类型校验命令，记录错误数与具体位置。

### 3.2 关键路径组件深度分析
对每条关键路径，逐项检查：

| 检查项 | 深度审计重点 |
|---|---|
| **数据加载与竞态** | `useEffect` / `watch` 依赖项是否完备；异步请求是否有防竞态与过期丢弃逻辑 |
| **刷新与列表联动** | CRUD 操作后列表是否正确重新请求并更新视图；避免因为缓存或去重 Key 导致视图未刷新 |
| **异常兜底处理** | 严禁 `.catch(() => {})` 静默吞错导致页面白屏；必须提供用户可见的错误提示或兜底 UI |
| **状态三态完整性** | 数据视图的 Loading（骨架屏/指示器）、Error（重试机制）、Empty（空状态）是否全部覆盖 |
| **表单与边界校验** | 必填项、类型、超长文本、特殊字符、非法输入边界 |
| **破坏性操作二次确认** | 删除、重置、批量变更等操作是否具备二次确认（Modal / Popconfirm） |
| **内存泄漏与事件清理** | 组件卸载后定时器、原生事件监听器、未完成的 Promise/AbortController 是否正确清理 |

### 3.3 API 层契约审计
- 接口路径、参数与后端文档规范的一致性；
- 业务错误码分支处理（HTTP 200 下的 `code !== 0` 或 `code !== 200` 业务异常拦截）；
- 鉴权凭证对所有受保护接口的覆盖情况。

### 3.4 安全与健壮性
- 敏感信息（密钥、私有 Token）是否硬编码在前端客户端代码中；
- XSS 防御与用户输入安全渲染。
