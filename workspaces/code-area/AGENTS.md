# Pi Agent 运行时工作区指南 (AGENTS.md)

欢迎使用 **Pi Desktop Lite** 代码工程工作区 (`code-area`)。

---

## 🤖 架构定位：全局编码技能调度中枢 (Hub & Routed Workspace)

当前 `code-area` 工作区作为 **Pi Agent 的全局编码技能集与调度中枢**：
1. **技能中枢（Hub）**：当前物理工作空间包含各类预置或由开发者扩展的专业编码技能库（`.agents/skills/`）；
2. **路由工作区（Routed Project Target）**：实际需要阅读、分析、修改、测试与构建的目标项目代码位于内设的「路由工作区」绝对路径下；
3. **免污染铁律**：`code-area` 自身目录绝对不创建、修改或污染项目业务代码，所有临时产物与代码变更严格作用于「路由工作区」；
4. **命令与路径锚定**：执行 Shell / Terminal / Git / Npm / Cargo 等指令时，必须显式以路由工作区为工作目录执行，读写文件必须以路由工作区绝对路径或相对于路由工作区的路径为准。

---

## 📁 核心操作铁律与规约

- **目标项目优先**：所有用户提问中的代码分析、重构、修复、编写任务，目标一律默认为当前绑定的路由工作区；
- **目标规约与技能无缝对齐**：会话启动时，宿主已自动将目标路由项目的 `AGENTS.md`（或 `AGENT.md`）规约、`README.md` 文档以及命中映射的专业技能（`.agents/skills`）注入上下文，执行任务时必须严格对齐目标项目的技术架构与编码规范；
- **分流调度内置技能**：根据任务需求分流唤醒 `code-area` 内置的相关技能（如重构、审查、Git 流水线等）；
- **最小动作与免产物铁律**：严禁未经用户显式授权擅自创建或重定向输出文件（如 `output.txt`、`temp.txt` 等）；纯分析、审查、问答与解释任务一律直接在对话流中输出 Markdown；如必须执行探针脚本或中转数据，必须严格遵循宿主 `temp-file-hygiene` 约束将文件暂存至沙盒临时目录（`~/.pi-dl/temp/`）并保证即用即删；
- **任务量级监测与计划执行 (Task Complexity & Planning)**：
  - **任务量级自觉监测与分流**：开始行动前先评估任务规模与复杂度。
    - **小型/轻量任务**（如单点问答、单文件微调、代码解释、简单查阅）：**严禁**输出任务计划，直接作答或执行，杜绝冗余开销与对话膨胀；
    - **中大型/多步任务**（如涉及多个文件修改、架构重构、深层调试验证、复合功能实现）：在首次调用工具或修改前，**必须先在输出中制定标准 Markdown 执行计划清单**；
  - **计划清单格式规范（严格联动桌面端计划执行面板）**：
    - 计划标题规范使用 `## 执行计划` 或 `**执行计划**`；
    - 步骤条目必须使用标准 Markdown 任务列表语法：`- [ ] 步骤描述`（至少包含 2 项明确子任务）；
    - 阶段推进时，随着各步骤执行完成，在随后的回复或阶段性汇报中及时将已完成项回写勾选为 `- [x] 步骤描述`，驱动前端进度指示器与划线联动，确保进度透明可追踪；
- **切换与配置门禁**：`code-area` 必须绑定有效的路由项目路径，不可空置运行。
